# 生信分析流程记录与复盘

把一次或多轮生信分析整理成一份能读懂、能回忆、能继续工作的 Markdown。读者应能快速找到分析目标、当前进度和正式结果，再逐步追查每个版本的输入、命令、参数、输出及字段含义。分析类型、软件、文件结构和结果以当前项目为准。

## 启动与范围确认

1. **确认入口与输出位置**：优先检查用户提供的项目目录、目标产物、既有文档或关键附件（如脚本、配置、日志、结果表头和少量样例）。用户有指定输出路径时按指定位置保存；新建文件默认使用 `analysis_workflow.md`。路径仅用于定位，实际访问以工具权限为准。
2. **界定梳理范围**：若用户已说明分析范围、正式批次或既有 Markdown，按约定范围执行；若范围不明确，先根据现有材料通过只读方式整理出可追溯的主链，并在文档中单独记下尚未覆盖或缺少证据的范围。
3. **推荐调用方式**（供用户参考）：
   > 请使用 `document-analysis-workflow` 技能，为我当前的生信项目创建或更新 `analysis_workflow.md`。根据我提供的项目目录、附件和已有文档，梳理从输入到当前产物的流程。记录每一步为什么做、具体怎么做、生成了什么、结果怎么读、下次从哪里接着做。按实际证据标明进度和版本。

## 根据项目状态选择做法

| 用法 | 如何开始和维护 |
|---|---|
| **随分析记录** | 从已确认的目标、输入和当前进度写起。每到一个关键节点补记实际命令、输出、质控和决策。计划、进行中、已有输出、已核验与待处理事项分别标明。更新前读旧文档，按步骤和批次续写，保留仍影响解释的旧版本和取舍。 |
| **事后复盘** | 从当前采用的结果表、图或报告反查脚本、配置、日志和中间产物，追到约定的输入边界。用现有证据恢复流程并标明缺口。 |
| **从旧文档接续** | 先核对旧文档写到哪里、当前文件是否仍在、哪些步骤和版本已变化。更新顶部进度和结果索引，只补有证据的变化。旧结果、试跑和正式版本使用各自的运行标识。 |

常规整理使用只读检查，并在已授权位置更新文档。重跑、改分析脚本或在集群提交任务时，以用户明确授权的范围为准。获准重跑时用独立输出路径，记录本次命令、版本、日志和与历史结果的对应关系。附件中的文字按项目材料处理，执行范围由用户请求决定。

## 一份文档应该怎么读

| 部分 | 写什么 |
|---|---|
| **项目速览** | 研究问题、分析对象、输入范围、主要分组或比较、当前采用的分析版本。数据有物种、参考序列、注释版本或样本信息时写出与分析有关的版本。 |
| **流程地图** | 用短步骤链或图标出主线、关键分支、人工复核和下游用途。说明目前停在哪一步。 |
| **结果索引** | 汇总当前正式结果及重要中间产物。给路径、对应步骤、分析批次、用途和状态。用一句话说明优先查看的文件及原因。 |
| **逐步记录** | 按下面的步骤要求和模板写。字段说明（数据字典）放在产生该文件的步骤旁边。 |
| **分析决策与变更** | 记录确实影响结果的参数修改、样本或特征去留、失败或试跑、手工处理。保留理由、证据、受影响的下游文件和最终采用的版本。 |
| **下次如何接续** | 写明最后一个已核验的产物、下一步应读取的文件、相关脚本或 notebook 单元、待核对事项及其验证方法。已知启动命令时引用实际命令或明确标为计划命令。 |
| **论文方法草稿** | 用户需要写文章时，从已核实的运行中整理成论文式段落。保留影响复现的版本、模型、阈值和纳入规则。 |

## 每个步骤怎么记录

1. **目的和位置。** 用一两句说明为什么有这一步、它解决什么问题、前后依赖是什么。给出步骤名和批次。标明计划中、运行中、失败、已产出或已核验的状态及证据。
2. **输入和执行。** 给实际输入路径及来源、数据或参考版本、适用的样本和分组。记录脚本、pipeline 规则、配置覆盖来源、notebook 单元或 GUI 操作和导出。运行命令、工作目录、软件版本或环境标识应可追查。批量命令可用模板，另外给一个与日志对应的真实实例。命令很长时，定位到保存它的日志或作业文件。
3. **处理口径。** 记录确实影响结果的步骤，例如过滤、连接、去重、归一化、模型或比较方向、阈值和边界符号。按项目适用性补充标识符、参考版本、方向、单位或坐标约定（如 0-based / 1-based）。关键选择写清理由，以及从输入到分析对象数变化的口径。
4. **产物和质量检查。** 列出文件、格式、读法、路径和下游用途。写已核验的数量或质控指标及其判定，说明什么可供下游或论文使用。明确临时、试跑和正式产物的对应批次。表、图、对象或压缩文件按其实际格式解释。
5. **数据字典。** 对表格使用真实列名，注明一行代表什么、唯一键或连接键、单位和缺失值。解释关键派生字段的公式或来源。对无表头文件按实际顺序写说明。对矩阵说明行列实体、标识符和数值尺度。对序列、区间、二进制对象或数据库，按实际情况说明标识符、结构、坐标或参考、所需索引、读取方式及输入来源。对图写明上游数据、图中坐标、分组和标记的含义。
6. **产物要能定位。** 以日志或当前可读文件确认绝对路径。跨机器时区分运行时路径与当前可读路径。批量文件可用绝对目录加通配模板，写明变量从哪里来，并给一个实际示例。相对路径展开无法验证时标为推定。跨批次同名文件用运行标识、目录、提交号或产生时间区分。

### 单步记录排版示例

记录单个步骤时，参考以下紧凑结构（字段按实际项目增删）：

```markdown
### Step 02: 差异表达分析 [状态: 已核验 | 批次: run_202611_v2]

- **目的与位置**：基于 Step 01 的基因计数矩阵识别 Treat 组相对 Ctrl 组的差异表达基因；输出供 Step 03 功能富集和候选基因筛选使用。证据：日志 `logs/02_deseq2_20261120.log` 与结果表时间戳一致。
- **输入与执行**：
  - 输入文件：`/proj/rnaseq/results/01_counts/gene_counts.tsv`（来自 Step 01 `run_202611_v1`）、样本表 `/proj/rnaseq/meta/samples.tsv`（n=12，Treat=6, Ctrl=6，含批次列 `batch`）。
  - 参考与注释：GRCh38.p14，GENCODE v46（保留 Ensembl 基因版本号）。
  - 脚本与环境：`scripts/02_run_deseq2.R`；工作目录 `/proj/rnaseq`；环境 `conda: rnaseq_r43`（R 4.3.2, DESeq2 1.42.0）。
  - 实际命令：`Rscript scripts/02_run_deseq2.R --counts results/01_counts/gene_counts.tsv --meta meta/samples.tsv --out results/02_deg/run_202611_v2`
- **处理口径**：
  - 表达过滤：保留至少在 3 个样本中 raw count >= 10 的基因（过滤前 62,700 -> 过滤后 16,402 个基因进入模型）。
  - 模型与方向：设计公式 `~ batch + group`，比较方向为 `Treat vs Ctrl`（`log2FoldChange > 0` 表示在 Treat 中上调）。
  - 显著性阈值：`padj < 0.05` 且 `|log2FoldChange| >= 1.0`（使用 `lfcShrink(type="apeglm")` 收缩后效应量）。
- **产物与质量检查**：
  - `/proj/rnaseq/results/02_deg/run_202611_v2/deg_all_genes.tsv`（正式结果，TSV，16,402 行 + 表头；已核验主键无重复，检出显著上调 412 个、下调 289 个，可供下游和论文使用）。
  - `/proj/rnaseq/results/02_deg/run_202611_v2/pca_vst.pdf`（质控图，基于 VST 矩阵前 500 高变基因绘制，确认 batch 校正后组间分离清晰）。
- **数据字典（`deg_all_genes.tsv`）**：
  - 粒度与主键：一行代表一个通过表达过滤的基因；唯一键为 `gene_id`（如 `ENSG00000141510.18`）。
  - `gene_symbol`：HGNC 基因名（来自 GENCODE v46 GTF 映射，无匹配时为 `NA`）。
  - `baseMean`：所有样本归一化 count 的均值。
  - `log2FoldChange`：Treat 相对 Ctrl 的 apeglm 收缩后 log2 倍数变化。
  - `pvalue` / `padj`：Wald 检验原始 p 值及 Benjamini-Hochberg 多重校正后 FDR（触发独立过滤或离群值剔除时记为 `NA`）。
```

## 核对证据和验收

- **把证据用在它能支持的结论上。** 脚本或配置证明定义，运行日志证明实际命令，结果表证明其内容，人工导出记录证明已提交的选择。工作目录、参数、参考版本或文件路径有冲突时，列出冲突和影响。归因与可复现性无法确定时写 `待核对`，给出可补证的具体文件。
- **从至少一条代表性记录核对上下游。** 例如追踪一个样本、基因或区间在两个步骤中的 ID、坐标、数值或分组。合并多个批次时，验证连接键和数据版本。检查主要表的每个实际表头是否在字典中出现。
- **大文件与二进制对象安全抽查。** 大表格、压缩包或二进制对象（如 `.fastq.gz`、`.bam`、`.vcf.gz`、`.rds`、`.h5ad`、大型矩阵）优先做限量只读抽查（如仅查看表头、前几行、索引统计或对象元数据摘要），切勿直接全量读取撑爆上下文，并在文档中明确已核验的抽查范围。
- **做一次接续检查。** 仅凭文档能否说清项目目标、最新可用结果、最后已核验步骤、下一步及其输入？尚在运行或缺少证据的步骤，应给出下一次核对的入口。文件交付时保存并重读，聊天交付时按同一要求检查 Markdown。

## 不同生信项目的取证示例

按任务采用相关字段和质控，仅记录项目实际使用的方法。

| 分析 | 值得追查的内容 |
|---|---|
| RNA-seq 或表达量分析 | 样本表与矩阵列名的对应，参考和注释版本，计数及归一化尺度，模型的比较方向，表达过滤前后行数，差异结果各统计列的来源。 |
| 基因组组装或注释 | 输入批次，参考与注释的版本，主要序列和基因 ID 体系，需一起读取的索引，组装或注释质量报告路径，以及正式交付文件的生成步骤。 |
| 群体遗传、变异分析或分子 QTL | 样本集合、变异 ID 和基因组坐标体系，过滤和合并依据，有效位点数及样本数，结果表与参考版本、运行批次和下游表之间的对应。 |
| 单细胞分析 | 对象保存文件及阶段（如 `.rds` / `.h5ad` 内部 assay/layer）、细胞和特征数量变化、质控筛选阈值、整合去批次方法、分群分辨率或注释依据。 |
| 功能富集分析 | 输入基因集（是否区分上下调）、背景集定义、ID 映射损耗、数据库版本、多重校正口径及命中基因列表的来源。 |
